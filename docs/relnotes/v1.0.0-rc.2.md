Android 16 (crDroid) for the **Huawei MateBook E Go** (Snapdragon 8cx Gen 3 /
SC8280XP) on a **mainline Linux kernel**, with hardware Vulkan on the Adreno 690.

The second **release candidate for 1.0**. Compared with 1.0.0-rc.1: **the
M-Pencil stylus has a driver**, **palm rejection** in the touch driver,
**Wi-Fi stays connected in standby** and recovers from firmware crashes,
**lower standby power** (the audio DSP can sleep now), a **lower-latency audio
path for rhythm games**, the USB-C port next to the power button is back to
**USB 3** with several role-switching fixes, and *Wild Rift* **no longer
closes at launch**. To get past some games' environment checks, the kernel now
**reports a disguised version string** — see below.

## How this candidate was tested

previous development build, not a fresh install). On this exact build:
release acceptance (A tier: **47 passed, 0 failed**, 1 warning = the two known

## Stylus and touch

* **The Huawei M-Pencil works** (pressure, hover, tilt, side double-tap) — it
  is sensed by the touch screen's second controller chip, which now has a
  driver, plus a small service that handles the pen's charging/pairing
  controller. Tested by the contributor on their own machine with the same
  code; **not tested on this build with a real pen yet**.
  <!-- PR #27（社区贡献）：patches/0079（触摸从片驱动）、0080（DT）、gk3pend（d44b5fc）、cmdline usbcore.quirks（f704ce3）、电量节点 sepolicy（21845a0）、
       复位后重新握手（#45：a1b4f93 / 443f592）。10-18 本构建：gk3pend 常驻、开机后 0 次崩溃，内核 himax-hx83121a-pen 在出帧；没拿笔测。 -->
* **Palm rejection**: a palm or the side of a hand on the screen is now
  recognised, and touches that turned out to be part of it are withdrawn (apps
  see a *cancel*, not a tap). The game touch preset turns this off so that a
  thumb near the edge is not swallowed. Tested by the contributor; not on this
  build yet.
  <!-- PR #30：patches/0081 / 0082（8c60f64 / 7b02ea5 / 230a3a7），game 预设关 29a61c9。 -->

## Wi-Fi and standby

* **Wi-Fi stays connected in standby.** Before, every standby disconnected
  Wi-Fi and powered the chip off, and it reconnected on every wake. Messages
  still arrive only when the system wakes up on its own — data from the network
  cannot wake the machine yet (see Known issues). Tested on this build.
  <!-- #40：a83221d（wowlan_triggers=disconnect gtk_rekey_failure）；10-18：iw phy phy0 wowlan show = enabled，s2loop WOW=1 3/3。叫不醒：#46 作者实测（known-limitations「待机时收不到消息推送」）。 -->
* If the connection drops during standby, the tablet now **reconnects with the
  screen off**; before, it stayed offline until the screen came on. When the
  Wi-Fi firmware occasionally declines to go into its standby mode, that
  standby is retried a moment later instead of dropping the connection.
  Tested by the contributor; not on this build yet.
  <!-- #46：0104（ath11k_scan wakeup source；10-18 本构建开机扫描时 active_count 19，在工作）、0105（-EBUSY 重试，c7e7c0c 修了与 0100 的交互）、0103（mac80211）。 -->
* **Wi-Fi firmware crashes are recovered from**, also when they happen during
  standby. Before, a crash could take the kernel down or leave Wi-Fi dead
  until the next cold boot. Tested by the contributor (with injected crashes).
  <!-- #44：0097–0102（44db121 / 8649323）；作者在 PR 里的注入测试。 -->
* **The audio DSP can sleep**, so standby uses less power: the audio codecs
  no longer keep it awake. Tested on this build (the DSP's sleep counter now
  moves; it stayed at 0 before). How much battery this saves has not been
  measured on this build; the contributor measured about 0.63 W in standby
  with this and the Wi-Fi changes, against about 0.74 W before.
  <!-- #46 的 0106–0110（主线 7.3 的 5 个 LPASS 补丁 backport）。功耗数字出自 #46 描述的过夜表，那组内核还带着后来拆出去的 0111 与 cmdline 改动 ⇒ 只能当参考。 -->

## USB-C

* The port **next to the power button is back to USB 3** speed (it had been
  held at USB 2), and a power rail it needs is now kept on — this fixes the
  board resetting when it went into standby while acting as a USB device.
* The port's role (host or device) now follows what is plugged in, handled by
  a proper USB port service instead of a script; plugging or unplugging during
  standby wakes the machine.
* Several fixes in the USB-C controller driver (UCSI), on their way upstream.
* All tested by the contributor; **not tested on this build with peripherals
  yet**.

## Games

* ***Wild Rift* no longer closes right after launch**: it reaches the
  user-agreement screen. Whether a match can be played has not been tested.
  The game assumes 64-bit processes never get memory addresses above 2^39;
  the kernel now hands out addresses below that by default.
  <!-- #17 / #15；patches/0078（5b5534c）；known-limitations「Wild Rift」一条（dev.11 起）；GAME-7 ⬜。 -->
* **The kernel reports a disguised version**, `6.6.30-android15-8-…`, because
  some games refuse to run on a kernel that calls itself 7.x. The kernel that
  runs is Linux 7.2.9. This is deliberate and has side effects: bug reports and
  crash records show the disguised version, and the KernelSU manager takes the
  kernel for `android15-6.6` — **do not use its *Install* / LKM patching**.
  Checked on this build: nothing else in the system changes behaviour.
  <!-- 0085（ec8847e）；GAME-1：源码排查 docs/source-audit-20261018.md 任务 B，10-18 上机 5 项（gaming.md §4.1）；known-limitations 第一节。 -->
* A netlink privacy boundary that Android's policy already asks for: ordinary
  apps can no longer read the Wi-Fi card's hardware MAC address or the list of
  other devices on the local network; and the system server no longer needs writable
  executable memory. Large OpenGL ES games keep more of their shader cache
  between runs.
  <!-- 0084（GAME-2，d791908 / ec8847e）；53b34ff（GAME-3，10-18 全机 avc 无 execmem）；106777c（issue #34，blob cache 多文件）。 -->

## Known issues

<!-- 只写本版特有 / 本版有变化的；长期限制在下面的摘要里。 -->

* **Do not tap *Erase all data* in Settings unless you mean it — and do not rely
  on it either.** Same as rc.1: the boot entry is expected to carry it out, but
  the erase itself has not been tested. Use the graphical installer's
  *Reinstall Android*.
  <!-- B6 / E10（用户 10-06 定不测）。 -->
* **Push notifications are late in standby**: usually a minute or two, sometimes
  about three. Wi-Fi stays connected, but incoming data cannot wake the machine
  yet.
  <!-- known-limitations「No push notifications while in standby」（fae43fa）。 -->
* **The KernelSU manager misreads the kernel** (see *Games*): do not use its
  *Install* / LKM patching.
* **System updates and slot switching fail** on hand-partitioned disks whose
  EFI partition has a non-standard name — see rc.1's notes for the one-line fix.
* Machines where Windows was deleted by hand may still offer *Restart to
  Windows*; INSTALL now explains how to remove it.
