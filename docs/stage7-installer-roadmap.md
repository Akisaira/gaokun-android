> ⚠️ **C 版源码（`live/installer/`、`scripts/live/gen-strings.py`）2026-09-26 已删**（改 Flutter，M0 验收过后）。

> 用户 2026-08-23 给出的完整需求。这份文档的作用是**定顺序**：

## 顺序，以及为什么是这个顺序

### 第 0 步（先做，因为它挡着所有后面的）：文案改成运行期加载

现在文案是**编译期宏**（`#define S_WELCOME_TITLE "..."`）。多语言要求
**运行期**能换，而后面还要新增 5 个界面 —— 等界面写完再改，就要动每一屏。

★ 做法：生成器改成同时出 `enum` 和一张表，宏名不变
（`#define S_WELCOME_TITLE gk3_s(STR_WELCOME_TITLE)`），
于是**界面代码一行都不用改**，而字符串来源变成"启动时从介质上加载，
加载不到就用编译进去的中文"。

### 第 1 步：输入模型（键盘 + 焦点）

现在只有"点哪算哪"（hit_test）。键盘要求**焦点**概念：Tab/方向键移动焦点、
回车确认、Esc 返回。而 #9（配 WiFi 要输密码）和 #5（编辑分区大小）
都需要**文本输入**。

⚠️ 这一步也决定了触摸和键盘怎么共存：焦点框只在用过键盘之后才显示，
否则纯触摸用户会看到一个莫名其妙的高亮框。

### 第 2 步：缩分区（#1 #8）

用户先要的就是这个。技术上是安装器里**唯一会去动用户现有数据**的操作，
所以纪律要求最高：

* 先 `ntfsresize --info` / `resize2fs -P` 问"最小能缩到多少"，不自己猜
* NTFS 缩之前**必须**确认它是干净卸载的（脏 NTFS 缩 = 数据损坏），
  `ntfsresize` 会拒绝带 dirty 位的卷 —— 不要绕过它
* 缩之前把分区表备份到介质（已有）
* **两步走**：先 `ntfsresize --no-action` 做一次演练，通过了再真做
* 缩完先改文件系统、再改分区表（顺序反了会丢数据）
* ⚠️ Windows 的 WinRE 分区通常在末尾，挡着缩出来的空间 —— 要能识别并
  提示用户在 Windows 里禁用 WinRE，或者把它挪走（挪 = 另一个风险，暂不做）

### 第 3 步：专业磁盘分配（#5）+ 命令行逃生口（#7）

一个能改每个分区大小的界面。**命令行逃生口先做**，因为它便宜（切到 tty2
给个 shell，附一行 `sgdisk`/`parted` 的提示），而且它是"专业选项"没做完之前
的兜底 —— 有它在，高级用户不会被卡住。

### 第 4 步：网络（#9）+ 网络安装（#3）+ 分支选择（#4）

顺序有依赖：先能配网，才能谈网络安装；能网络安装了，才有"选哪个分支"
可谈（分支清单本身要从网上取）。

* 配网：扫 AP → 选 → 输密码（依赖第 1 步的文本输入）
* 网络安装：从 `ota.072172.xyz` 取一份清单（复用现成的 R2 布局），
  下载 payload 到 tmpfs 或直接流式写盘
* 分支：清单里列出变体（`ksu` / `gapps` / 两者 / 都不要），
  ⚠️ **变体是构建期决定的**（KSU 要编进内核、GApps 要进 super），
  所以安装器只是"选一个已经构建好的变体下载"，不是在设备上组装

## 几条现在就定下的决定

* **变体不在设备上组装。** KSU 编在内核里、GApps 在 super 里，都是构建期的事。
  安装器给的是"选哪个已构建的镜像"，别把它做成包管理器。
* **网络安装不做成默认。** 这台机器的 WAN 实测只有 1–2 MB/s（[TODO A8]），
  1.2 GB 的包要 10–20 分钟。默认仍是"U 盘里带 payload"，网络安装是给
  不想做大 U 盘的人用的。
* **多语言先只做中/英两种。** 文案是一个人写的，多加一种就要多维护一份；
  等真有人要别的语言再加。
* **不做磁盘加密选项。** 安装器再插一层加密只会让恢复变难（救援系统与"重新安装 + 保留数据"
  都要能直接读写 /data）。
  ⚠️ 2026-10-04 更正：这里原先写的理由"Android 自己的 FBE 已经在管 /data"是**错的** ——
  /data 从来没加密过：实机 `ro.crypto.state=unsupported`，`device/huawei/gaokun3/fstab.gaokun3:27`
  的 userdata 行没有 `fileencryption=`。用户定 1.0 也不加密、在文档里如实披露
  （`docs/v1.0-plan.md` B3 / D3）。

## ⬜ 还欠的（按重要性）

1. **WiFi 页要重做成两步式**。现在密码框挤在 AP 列表下面，列表一长就把按钮

3. **专业分区页的值没有回灌到 plan**。改了 super/userdata 的数字，

4. **`ADV.TOTAL` 的"可用总量"算法是拼的**（`plan_userdata_mib + 13776`），

5. 端到端真装一次（整盘 + 双系统各一次）。**从来没有真的装过一台机器。**

## ⚠️ 回来时要知道的三件事

### 1. 设备可以自己编译 —— 这是最快的迭代路径

live 系统是 Alpine、aarch64、有网。ssh 上去 `apk add build-base cairo-dev
pango-dev libdrm-dev libinput-dev eudev-dev`（约 300 MB，跑在内存里），
然后把三个源文件 scp 过去 `make drm`，**编译只要 1 秒**。
改一行到在真机上看见效果 ≈ 30 秒，不用重建镜像、不用拔插 U 盘。

⚠️ 装的编译工具和编出来的二进制**都在 tmpfs 上，重启即失**。
定稿之后必须重建一次镜像，否则 U 盘里还是旧的。

### 2. "卡顿"的真因是阻塞，不是渲染

实测：一帧 **6.1 ms**（164 fps）。我先后猜了"Pango 太慢"和"shell 开销大"，
量下来都不是（后端 10–160 ms）。真凶是 **WiFi 页在 UI 线程里等外部命令**
（扫描 3 秒、连接最多 35 秒）。已改成 fork 子进程 + 主循环轮询。

★ 顺带确认了一个值得留的优化：cairo **不要直接画在 DRM dumb buffer 上**。
那是 write-combining 内存，**读极慢**，而 alpha 混合每个像素都要读一次目标。
改成画在普通内存再整块 memcpy：**12.3 ms → 6.1 ms**。

### 3. 别再用 `screen++/screen--` 导航

分支屏（缩分区/连网/选版本）插在枚举中间，`SC_SOURCE - 1` 恰好是 `SC_SHRINK`
—— 于是"来源"页按返回会掉进一个用户没走过的分支。
⚠️ **我在枚举上方写了注释警告过这件事，然后照样用了 `screen--`。**
现在是 `nav_go` / `nav_back` 的栈。注释挡不住 bug，结构才行。

## 反复咬人的坑（本轮至少六次）

**生成代码时不要写反斜杠转义。** `\n` 会被中间层 collapse 成真实换行、
`\1` 被吃成 0x01 控制字符（那次最阴：守卫看着在那儿却从不触发）。
一律用 `chr(92)`、或者干脆换成不需要反斜杠的写法（`cut -d"'"` 而不是 sed 反捕获）。
